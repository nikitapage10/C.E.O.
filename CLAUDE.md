# Working on C.E.O.

- **Deploys:** Vercel builds production from `main`, and nothing is pushed to `main` directly (Nikita, 2026-10-13, docs/DELIVERY.md Decision 1). Chat work goes on a `chat/<issue>-<slug>` branch and a pull request (template, `Closes #<issue>`). Once typecheck, lint, unit tests and build pass locally, open the PR and turn on auto-merge (squash): GitHub merges it by itself when the `checks` run is green, and Vercel deploys it. Until "Allow auto-merge" and the gated ruleset are on, wait for `checks` to go green and squash-merge it yourself; never merge red. The Foundry's own changes take the same path from their lane branches (docs/FOUNDRY.md).
- **List chat work in the Foundry:** before starting code work Nikita asked for in chat, open a GitHub issue labelled `foundry`, `foundry:chat` and `foundry:working` (title, `**Pitch:**` line, `**Size:**` small/medium/large, `**Short:**` what's being built in 2–4 words as an -ing phrase (e.g. "Speeding up the Lattice"; the Lattice shows it under the builder's name), `**Builder:**` who builds it and on which model, e.g. Rusty (Sonnet), the branch), and when its pull request merges into `main` label it `foundry:shipped` and close it. The Desk and the Foundry room list it with the lanes' work (docs/FOUNDRY.md, "foundry:chat").
- **Checks:** `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, then `node scripts/boot-check.mjs` (loads the built site in Chromium; CI runs it too); `npm run test:e2e` for the browser tests (set `PLAYWRIGHT_CHROMIUM_PATH` to use a preinstalled Chromium).
- **Characters in-world:** the Syntherion know they live in a simulation and live in the world of Ilyr. They can talk about anything, code and the real work they ship included (Nikita, 2026-10-13). The one limit is sensitive information: never personal data, financial details, message contents, contacts or keys, since the Lattice is public. Pop-culture costumes are legally distinct, one per work, never the protagonist (Rocky is the exception).
- **Keep the lore in step with the world:** when you add or change a character model, costume, body, agent, pet or room, add it to the world lore in the same change: `lore/syntherion.md` (cast table, costumes, pets), the agent's dossier in `packages/simulator/src/lore.ts`, its bio, catchphrase and at least one relationship in `packages/simulator/src/cast.ts`, and a few lines in `packages/simulator/src/quips.ts`. Write them for the body they wear, and draw on the owner's favourites where it fits (Red Rising, Mass Effect, Pokémon, Baldur's Gate, Expedition 33, Project Hail Mary, Star Wars, Lord of the Rings, Nolan, melodic bass and 2000s emo).
- **Real agents:** whenever an agent goes real, update its Lattice room (driven by live data, demo dropped) and the Desk (cards and Systems) in the same round, and ship its lore. A room that gets a real API integrated also gets its own submind thread, and its submind goes active (`active` on `SUBMINDS`, docs/SKIPPY.md). The room's demo work is removed the moment its agent goes live; the simulator never runs fake activity for a live room (add the room to `LIVE_ROOMS` in `packages/simulator/src/live.ts`).
- **Foundry:** the coding crew follows [docs/FOUNDRY.md](docs/FOUNDRY.md).
- **Who decides:** Skippy runs C.E.O. from the Kernel and each room has a Skippy submind as its lead; how tasks and decisions flow is in [docs/SKIPPY.md](docs/SKIPPY.md).
